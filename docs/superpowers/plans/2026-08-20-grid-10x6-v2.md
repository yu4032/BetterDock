# 10×6 Home Grid Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an opt-in 10×6 landscape / 6×10 portrait home-grid profile to current LiquidDock 2.0 without regressing the existing 8×4 path or importing retired architecture.

**Architecture:** Keep `HomeGridHook` as the sole geometry/widget/margin owner. Add small pure profile/count/rotation policies and a narrow `HomeGridProfileOverlayHook` that changes only profile-sized Pad counts, normal Workspace GridConfig counts, and MIUI rotation metadata when 10×6 is selected.

**Tech Stack:** Java 17, Kotlin/Compose settings UI, Android/HyperOS Launcher private APIs, libxposed API101, JUnit4/Gradle.

**Spec:** `docs/superpowers/specs/2026-08-20-grid-10x6-v2-design.md`

## Global Constraints

- Current `main` (`eeadb4b4a37aa783c0a462afa524484ea54f9e72`) is the only production baseline.
- Do not port old screenshot capture, 307 capture state, SystemUI hooks, old Dock geometry, or RuntimeShader code.
- `HomeGridHook` remains the only owner of CellLayout geometry, widget frames, margins, row gaps, folder alignment, indicator placement, lazy-page preparation, workstation handling, and workspace refresh.
- `WorkspaceDropRuleHook` may only bypass MIUI's stock swap-pattern rule; occupancy/bounds remain vendor-owned.
- 8×4 remains the default profile and must remain behaviorally compatible.
- Verification requires `testDebugUnitTest`, `assembleDebug`, and the standard API101 artifact upload.
