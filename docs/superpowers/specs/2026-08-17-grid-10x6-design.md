# 10×6 Home Grid Design

## Goal

Add a selectable 10×6 landscape / 6×10 portrait home-screen grid without regressing the existing stock and 8×4 / 4×8 layouts.

## Configuration model

Use two canonical settings with one clear responsibility each:

- `home_grid_extended`: master switch for LiquidDock custom-grid hooks.
- `grid_profile`: selected extended layout, either `8x4` or `10x6`.

When the master switch is off, LiquidDock leaves the MIUI grid untouched regardless of the stored profile. When it is on, the selected profile defines landscape and portrait counts:

- `8x4`: landscape 8×4 / portrait 4×8.
- `10x6`: landscape 10×6 / portrait 6×10.

`home_grid_8x4` becomes a legacy migration input only. Existing `home_grid_8x4=true` migrates to `home_grid_extended=true` plus `grid_profile=8x4`. Existing false/absent state migrates to `home_grid_extended=false`; the stored profile defaults to `8x4` so enabling the feature later preserves the historical choice.

## Runtime architecture

Introduce a small `HomeGridProfile` value object/enum that owns:

- landscape column and row counts;
- portrait column and row counts;
- rotation block metadata.

`LiquidDockConfig.Grid` resolves both `enabled` and `profile` once at process startup. `MainHook` passes both into `HomeGridHook`. The master switch remains the only gate deciding whether custom-grid hooks may alter Workspace geometry.

The CellLayout geometry path remains count-driven. Existing cell-size, gap, margin, widget-frame and bounds checks must continue to use the actual `countX/countY` values rather than branch on one profile.

## Grid-count hooks

Do not implement 10×6 by globally replacing every `4` or `6` returned from `GridConfig`. That risks changing laptop All Apps and unrelated GridConfig instances.

The authoritative Pad cell-count compatibility hooks return the selected profile's orientation-specific counts only while `home_grid_extended` is enabled. GridConfig setter/getter normalization must be scoped so it only normalizes values that correspond to the selected normal Workspace profile and must preserve dedicated workstation All Apps geometry.

With the master switch off, stock behavior stays untouched.

## Rotation mapping

Keep MIUI's native occupied-matrix storage and transform implementation. LiquidDock only supplies compatible `LayoutTransformRuleGridChanged` metadata.

Generate 2×2 block origins from the selected even-sized profile rather than hard-coding coordinates:

- 8×4 contains 4×2 = 8 blocks.
- 10×6 contains 5×3 = 15 blocks.
- portrait metadata is the transposed block grid.

`totalBlocks` equals `(landscapeColumns / 2) * (landscapeRows / 2)`. `checkCellCount()` is bypassed only when the master switch is enabled and the current counts exactly match the selected profile or its portrait transpose.

## Widget behavior

Keep the current supported widget specs: 1×1, 2×1, 2×2 and 4×2. `WidgetGridSizing.gridRect()` already validates `cellX + spanX <= countX` and `cellY + spanY <= countY`; these checks remain authoritative for both 8×4 and 10×6.

Do not add automatic item relocation in this feature. Existing launcher migration/rotation behavior remains responsible for occupied-cell placement; this change only supplies a valid larger grid and rotation metadata.

## UI

Keep a two-level control in the Home Screen Grid page:

1. **可选扩展布局** — master switch.
2. **扩展布局规格** — list selector visible/enabled only while the master switch is on:
   - 8×4 / 4×8
   - 10×6 / 6×10

Grid margins, row-gap, indicator and widget-adaptation controls are enabled whenever the master switch is on. The selector does not contain a “system default” item; system-default behavior is represented exclusively by the master switch being off.

Update the Home summary so it mentions selectable 8×4 and 10×6 layouts.

## Compatibility and migration

- Existing `home_grid_8x4=true` users migrate to `home_grid_extended=true` and `grid_profile=8x4`.
- Existing `home_grid_8x4=false` or absent users migrate to `home_grid_extended=false`; `grid_profile` defaults to `8x4` without activating it.
- Existing canonical `home_grid_extended` and `grid_profile` values are never overwritten by migration.
- Import/export uses the canonical `home_grid_extended` and `grid_profile` settings.
- Legacy imports containing only `home_grid_8x4` are translated to the two canonical settings during import.
- No existing margin, row-gap, indicator or widget-adaptation values are reset when switching profiles.

## Tests

Add RED tests before production changes for:

1. profile parsing for `8x4` and `10x6`, with invalid values falling back to `8x4`;
2. legacy preference migration to the new master switch plus profile;
3. exact landscape/portrait counts for 8×4 and 10×6;
4. generated rotation blocks: 8 blocks for 8×4, 15 for 10×6, all origins in bounds and unique;
5. `checkCellCount` matching only the selected profile and transpose while the master is enabled;
6. 4×2 widget bounds at the right/bottom edges of a 10×6 / 6×10 grid;
7. Compose UI presents one master switch plus a two-option profile selector;
8. existing 8×4 contract tests remain green.

Run the full `testDebugUnitTest` suite and `assembleDebug` after implementation.

## Non-goals

- No folder-close blur lifecycle fix in this branch.
- No arbitrary delayed refresh added for 10×6.
- No automatic icon rearrangement or per-orientation position-memory redesign.
- No changes to Dock, workstation Dock, liquid-glass capture, stroke or shadow ownership.
