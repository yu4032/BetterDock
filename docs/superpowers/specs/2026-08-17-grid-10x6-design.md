# 10×6 Home Grid Design

## Goal

Add a selectable 10×6 landscape / 6×10 portrait home-screen grid without regressing the existing stock and 8×4 / 4×8 layouts.

## Configuration model

Use one persisted profile instead of multiple booleans:

- `stock`: MIUI native grid, no LiquidDock grid hooks.
- `8x4`: current landscape 8×4 / portrait 4×8 behavior.
- `10x6`: landscape 10×6 / portrait 6×10 behavior.

Add `grid_profile` as the canonical setting. Keep `home_grid_8x4` only as a legacy migration input. If `grid_profile` is absent, migrate `home_grid_8x4=true` to `8x4`; otherwise migrate to `stock`. Do not silently change an existing 8×4 user's layout.

## Runtime architecture

Introduce a small `GridProfile` value object/enum that owns:

- landscape column and row counts;
- portrait column and row counts;
- whether custom-grid hooks are enabled;
- rotation block metadata.

`LiquidDockConfig.Grid` resolves the persisted profile once at process startup. `MainHook` passes the resolved profile into `HomeGridHook`; it no longer passes an `enableGrid8x4` boolean.

The CellLayout geometry path remains count-driven. Existing cell-size, gap, margin, widget-frame and bounds checks must continue to use the actual `countX/countY` values rather than branch on one profile.

## Grid-count hooks

Do not implement 10×6 by globally replacing every `4` or `6` returned from `GridConfig`. That risks changing laptop All Apps and unrelated GridConfig instances.

The authoritative Pad cell-count compatibility hooks return the profile's orientation-specific counts. GridConfig setter/getter normalization must be scoped so it only normalizes values that correspond to the selected normal Workspace profile and must preserve dedicated workstation All Apps geometry.

Existing stock behavior stays untouched when the profile is `stock`.

## Rotation mapping

Keep MIUI's native occupied-matrix storage and transform implementation. LiquidDock only supplies compatible `LayoutTransformRuleGridChanged` metadata.

Generate 2×2 block origins from the selected even-sized profile rather than hard-coding coordinates:

- 8×4 contains 4×2 = 8 blocks.
- 10×6 contains 5×3 = 15 blocks.
- portrait metadata is the transposed block grid.

`totalBlocks` equals `(landscapeColumns / 2) * (landscapeRows / 2)`. `checkCellCount()` is bypassed only for the exact selected custom profile and its portrait transpose.

## Widget behavior

Keep the current supported widget specs: 1×1, 2×1, 2×2 and 4×2. `WidgetGridSizing.gridRect()` already validates `cellX + spanX <= countX` and `cellY + spanY <= countY`; these checks remain authoritative for both 8×4 and 10×6.

Do not add automatic item relocation in this feature. Existing launcher migration/rotation behavior remains responsible for occupied-cell placement; this change only supplies a valid larger grid and rotation metadata.

## UI

Replace the 8×4 boolean control with a single profile selector in the Home Screen Grid page:

- System default
- 8×4 / 4×8
- 10×6 / 6×10

Grid margins, row-gap, indicator and widget-adaptation controls are enabled whenever the selected profile is not `stock`.

Update the Home summary so it no longer implies that 8×4 is the only custom grid.

## Compatibility and migration

- Existing `home_grid_8x4=true` users must resolve to `8x4` after upgrade.
- Existing `home_grid_8x4=false` or absent users must resolve to `stock` unless `grid_profile` already exists.
- Import/export uses the canonical `grid_profile` setting. Legacy imports containing only `home_grid_8x4` are migrated before runtime use.
- No existing margin, row-gap, indicator or widget-adaptation values are reset when switching profiles.

## Tests

Add RED tests before production changes for:

1. profile parsing and legacy migration;
2. exact landscape/portrait counts for stock, 8×4 and 10×6;
3. generated rotation blocks: 8 blocks for 8×4, 15 for 10×6, all origins in bounds and unique;
4. `checkCellCount` matching only the selected profile and transpose;
5. 4×2 widget bounds at the right/bottom edges of a 10×6 / 6×10 grid;
6. Compose UI uses one profile selector and no longer treats `home_grid_8x4` as the live control;
7. existing 8×4 contract tests remain green.

Run the full `testDebugUnitTest` suite and `assembleDebug` after implementation.

## Non-goals

- No folder-close blur lifecycle fix in this branch.
- No arbitrary delayed refresh added for 10×6.
- No automatic icon rearrangement or per-orientation position-memory redesign.
- No changes to Dock, workstation Dock, liquid-glass capture, stroke or shadow ownership.
