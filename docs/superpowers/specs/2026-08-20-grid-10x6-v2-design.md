# 10×6 Home Grid Port Design (2.0)

## Goal

Port the device-validated 10×6 landscape / 6×10 portrait home-grid behavior from the historical 1.x development chain into the current 2.0 `main` architecture without importing retired capture, glass, Dock, or SystemUI code.

The existing 8×4 / 4×8 implementation remains the geometry baseline and must not regress.

## Design principles

1. **Single ownership per concern.** `HomeGridHook` remains the only owner of CellLayout geometry, margins, row gaps, widget frames, folder alignment, indicator placement, lazy-page preparation, workstation handling, and workspace refresh.
2. **Profile-specific code stays narrow.** 10×6 adds only the count and MIUI rotation-transform metadata that inherently depend on profile size.
3. **Pure policy before hooks.** Profile dimensions, GridConfig count resolution, rotation direction, and block remapping live in small Java policy/value classes with no Android/Xposed dependency.
4. **No broad vendor override.** Do not replace occupancy, vacancy search, CellLayout storage, or MIUI's native transform algorithm.
5. **No historical architecture resurrection.** Nothing from old screenshot capture, 307 capture state, SystemUI hooks, old Dock geometry, or RuntimeShader code is ported.

## Configuration model

Introduce canonical grid settings:

- `home_grid_extended`: master switch for custom home-grid layouts.
- `grid_profile`: selected profile, `8x4` or `10x6`.

`home_grid_8x4` becomes a legacy compatibility input only.

Migration rules:

- Existing canonical keys win and are never overwritten.
- Legacy `home_grid_8x4=true` becomes `home_grid_extended=true`, `grid_profile=8x4`.
- Legacy false or absent state becomes `home_grid_extended=false`; profile defaults to `8x4`.
- Existing margin, row-gap, indicator, and widget-adaptation values are untouched.
- Import/export uses canonical keys; legacy JSON containing only `home_grid_8x4` is translated during import.

The runtime config resolves `enabled` and `profile` once at process startup.

## Profile model

Add `HomeGridProfile` with two values:

- `GRID_8X4`: landscape 8×4, portrait 4×8.
- `GRID_10X6`: landscape 10×6, portrait 6×10.

It owns only dimension-derived facts:

- landscape/portrait columns and rows;
- profile matching against a count pair;
- total 2×2 rotation blocks;
- generated row-major 2×2 block origins.

Invalid persisted values normalize to `8x4`.

## Runtime architecture

### Existing `HomeGridHook`

Keep its current responsibilities and implementation intact as much as possible. It continues to establish the custom-grid geometry path and calculate CellLayout size from actual `countX/countY` values.

The current boolean name `grid8x4Enabled` should be renamed internally to a profile-neutral `customGridEnabled` only where doing so improves clarity; avoid a broad mechanical rename if it would inflate the diff without changing behavior.

### New `HomeGridProfileOverlayHook`

Install only when the master switch is on and the selected profile is 10×6. It may change only:

- Pad compatibility axis counts;
- normal Workspace `GridConfig` count setter/getter values;
- `LayoutTransformRuleGridChanged` profile-sized rotation metadata.

It must not own CellLayout margins, geometry, widget frames, indicator, folder, workstation All Apps, Dock, or refresh scheduling.

Workstation/laptop and non-Workspace GridConfig callers are excluded.

## GridConfig ownership

Do not infer orientation solely from global `Configuration`: during rotation, the global orientation can lead or lag the `GridConfig` object currently being applied.

For named normal Workspace configs, use semantic ownership:

- `land_grid` / landscape name → 10×6.
- `vertical_grid` / portrait name → 6×10.

For ambiguous compatibility-layer values, rewrite only the device-verified 8×4 intermediates:

- `8 -> 10`
- `4 -> 6`
- existing `6` or `10` stay unchanged.

Do not rewrite arbitrary counts.

## Rotation transform

Retain MIUI's native `LayoutTransformRuleGridChanged` transform and occupancy matrices.

For 10×6 only:

1. constructor post-state receives generated 2×2 block origins and `totalBlocks=15`;
2. `checkCellCount()` accepts exactly 10×6 or 6×10;
3. correct `mIsVerticalCellCount` at the narrow `get4x2WidgetCase()` boundary based on source/target transpose direction;
4. replace only the hard-coded ordinary-widget block index mapping in `getDstBlockXY()` with an ordinal mapping over non-reserved blocks.

The two native 4×2 SPECIAL_WIDGET slots remain handled by MIUI. The policy only generalizes the ordinary blocks around them.

## Widget and drag/drop behavior

Current `WidgetGridSizing` remains authoritative for widget frame allocation. Supported specs do not change.

Current `WorkspaceDropRuleHook` remains the only stock swap-rule bypass. It does not replace occupancy or bounds checking. The new master switch must feed it as `customGridEnabled` so both 8×4 and 10×6 get identical drop-rule treatment.

No automatic icon relocation or per-orientation position-memory redesign is part of this port.

## UI

Replace the current single `8×4` switch with:

1. **可选扩展布局** master switch.
2. **扩展布局规格** selector, enabled only when master is on:
   - `8×4 / 4×8`
   - `10×6 / 6×10`

Widget adaptation, margins, row gaps, and indicator controls remain under the master switch and are profile-independent.

The selector has no “system default” option; stock behavior is represented only by the master switch being off.

## Error handling

- Missing optional private methods/classes: log and fail closed for the 10×6 overlay, leaving the existing base custom-grid path rather than installing a partially inconsistent transform.
- Unknown GridConfig name: use only the conservative intermediate-value mapping, never assume orientation.
- Workstation/laptop callers: preserve vendor behavior.

## Tests

Write RED tests before production changes for:

1. profile parse/normalize and dimension methods;
2. 8×4 = 8 blocks, 10×6 = 15 blocks; unique/in-bounds origins;
3. GridConfig name ownership and conservative intermediate rewrites;
4. source rotation direction for 10×6 <-> 6×10;
5. ordinary block remap with zero, one, and two 4×2 special widgets;
6. canonical config migration from `home_grid_8x4`;
7. runtime config exposes `enabled + profile`;
8. Compose UI has one master plus a two-profile selector;
9. WorkspaceDropRuleHook is gated by the profile-neutral custom-grid master;
10. 10×6 / 6×10 widget edge bounds;
11. all existing 8×4, workstation, widget, zero-copy, and config tests remain green.

Verification requires full `testDebugUnitTest`, `assembleDebug`, and standard API101 artifact upload.

## Non-goals

- No changes to liquid-glass zero-copy rendering or Prismal.
- No screenshot/capture code.
- No SystemUI hooks.
- No Dock geometry or workstation Dock changes.
- No arbitrary custom grid sizes beyond the two explicit profiles.
- No automatic icon rearrangement or new layout-memory subsystem.
